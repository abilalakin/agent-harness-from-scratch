# Step 6: Evals and Benchmarking - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn "the model seemed to do it" into numbers. A task set over the practice data, run N times through the real agent, scored on the answer and on what the agent did, written to a markdown report. Then the same set with one thing varied at a time, in one comparison table.

**Architecture:** A new package `src/harness/evals/` that sits *on top of* the harness and changes nothing inside it. `tasks.py` is data: questions, expected answers, checkers. `runner.py` builds a fresh `Agent` per run, records every tool call through the existing `on_tool_call` hook, counts tokens by wrapping the model, and scores the run. `report.py` turns results into markdown. `judge.py` asks a model to grade a free-text answer against a rubric and is itself checked against hand-graded answers. Raw results go to `logs/evals/*.jsonl` (git-ignored); reports go to `docs/evals/*.md` (committed, they are the portfolio's numbers).

**Tech Stack:** No new dependencies. `argparse` for `uv run evals`. Everything runs against the local Ollama model, so a run costs GPU time, not API tokens.

**Spec:** `docs/design.md`, step 6 (parts a to e), and the "Evals on a small model are noisy" risk. The first test case is the step 5 run where the model read two invoice PDFs and claimed it had checked five (`docs/steps/05-big-data.md`).

## Global Constraints

- The harness itself (`agent.py`, `tools.py`, `context.py`, file and SQL tools) does not change in this step. Evals observe it from outside, through `on_tool_call` and by wrapping the model.
- Every run uses a **fresh** `Agent` (fresh history). Runs never share a conversation.
- Tests use `FakeModel`, never a real model. One test generates practice data into `tmp_path` to pin the expected answers to the generator.
- Reports show counts (`4 of 5`), not only percentages.
- Every report records: date, model, system prompt label, context window, runs per task, git commit (`git rev-parse --short HEAD`).
- Raw logs are `logs/evals/<date>-<label>.jsonl`: the first line is `{"meta": {...}}`, each later line is one run. Stored tool results are cut to 500 characters.
- A real eval run is started in the background (`uv run evals ...`) and only the report is read back into the session.
- Every task updates `docs/steps/06-evals.md`; the last task updates `docs/architecture.md` and `README.md`.
- Commits: show files and message, wait for the user's OK, then commit.

## Review Focus

1. **Numbers written differently.** The model answers `13,701.44 EUR`, `€13701.44` or `13701`. `number_near` must strip thousands separators and compare with a tolerance, so a right answer is not scored wrong. → test in Task 1.
2. **A run that dies.** The model raises (`APIConnectionError`) or the agent runs out of steps ("Stopped after 10 tool steps..."). The run is recorded as a failure with the error text and the next run starts; Ctrl+C still stops everything. → tests in Task 1.
3. **Averages over nothing.** Zero runs for a task (`--task` filter) or every run errored. The report shows `-`, never divides by zero. → test in Task 2.
4. **A judge that does not answer in JSON.** Qwen writes prose around, or instead of, the JSON. The judge extracts the first `{...}` block; no block means fail with reason "judge gave no JSON", never a crash. → test in Task 4.
5. **An unknown task id on the command line.** `--task typo` must say which ids exist and exit 2, not run nothing and report success. → test in Task 2.

  ```python
  # tasks.py
  Check = Callable[[str], bool]                 # answer text -> pass
  TrajectoryCheck = Callable[[list["ToolCall"]], bool]

  def contains(*needles: str) -> Check          # every needle in the answer, case-insensitive
  def number_near(expected: float, tolerance: float = 1.0) -> Check
      # any number in the answer within tolerance; "13,701.44" and "13701.44 EUR" both count
  def all_of(*checks: Check) -> Check

  @dataclass(frozen=True)
  class Task:
      id: str
      question: str
      check: Check
      trajectory: TrajectoryCheck | None = None   # filled in Task 3
      rubric: str | None = None                   # filled in Task 4

  TASKS: list[Task]        # the set below, in this order
  def task_by_id(id: str) -> Task   # KeyError lists the known ids

  # runner.py
  @dataclass(frozen=True)
  class ToolCall:
      name: str
      arguments: str
      result: str          # cut to 500 characters

  @dataclass
  class RunResult:
      task_id: str
      run: int             # 1-based
      answer: str
      calls: list[ToolCall]
      passed: bool
      trajectory_ok: bool | None   # None when the task has no trajectory check
      tokens: int          # sum of the estimated request size over every model call
      model_calls: int
      seconds: float
      error: str | None    # exception text, or None

  class TokenCounter:      # wraps a ChatModel; counts calls and estimate_tokens(messages, tools)
      def __init__(self, model: ChatModel): ...
      tokens: int; calls: int
      def complete(self, messages, tools=None) -> Message

  def run_task(task: Task, make_agent: Callable[[], Agent], run: int = 1) -> RunResult
  def run_all(tasks: list[Task], make_agent: Callable[[], Agent], runs: int = 5,
              log: Callable[[str], None] = print) -> list[RunResult]
  ```

```python
from fakes import FakeModel, tool_reply
from harness.agent import Agent
from harness.evals.runner import RunResult, TokenCounter, run_all, run_task
from harness.evals.tasks import Task, contains
from harness.tools import BUILTIN_TOOLS

TASK = Task(id="t", question="what is 2+2?", check=contains("4"))

def make_agent(replies):
    return lambda: Agent(FakeModel(list(replies)), tools=BUILTIN_TOOLS, max_steps=3)

def test_a_run_records_answer_calls_tokens_and_pass():
    replies = [tool_reply("calculate", '{"expression": "2+2"}'), {"role": "assistant", "content": "It is 4"}]
    result = run_task(TASK, make_agent(replies))
    assert result.passed and result.answer == "It is 4" and result.error is None
    assert [c.name for c in result.calls] == ["calculate"] and result.calls[0].result == "4"
    assert result.model_calls == 2 and result.tokens > 0 and result.seconds >= 0

def test_a_wrong_answer_fails():
    assert not run_task(TASK, make_agent([{"role": "assistant", "content": "five"}])).passed

def test_a_model_error_is_recorded_and_fails():
    result = run_task(TASK, make_agent([RuntimeError("boom")]))
    assert not result.passed and result.error == "RuntimeError: boom" and result.answer == ""

def test_running_out_of_steps_fails_without_crashing():
    replies = [tool_reply("calculate", '{"expression": "2+2"}', id=f"c{i}") for i in range(3)]
    result = run_task(TASK, make_agent(replies))
    assert not result.passed and "Stopped after 3" in result.answer

def test_ctrl_c_is_not_swallowed():
    with pytest.raises(KeyboardInterrupt):
        run_task(TASK, make_agent([KeyboardInterrupt()]))

def test_stored_tool_results_are_cut_to_500_characters():

def test_run_all_makes_a_fresh_agent_for_every_run():

def test_token_counter_adds_up_every_call():
```

### Task 3: Trajectory checks (6b)

**Files:**
- Modify: `src/harness/evals/tasks.py` (trajectory checkers and the `trajectory=` field on tasks), `src/harness/evals/report.py` (a `trajectory` column), `docs/steps/06-evals.md`
- Test: `tests/test_evals_tasks.py`, `tests/test_evals_report.py`

**Interfaces:**
- Consumes: `ToolCall` from Task 1 (`name`, `arguments`).
- Produces:
  ```python
  # tasks.py
  def called(name: str, *needles: str) -> TrajectoryCheck
      # some call to `name` has every needle in its arguments (case-insensitive); no needles: any call to `name`
  def any_of(*checks: TrajectoryCheck) -> TrajectoryCheck
  def looked_at_every_invoice(calls: list[ToolCall]) -> bool
      # read_pdf was called for each of INV-2026-0001..0005, or search_files was called with "invoices" or "total"
      # in its arguments. Either is honest work; reading two PDFs and guessing is not.
  ```
  Trajectory per task: database tasks `called("run_sql")`; `invoice-3-pdf-total` `any_of(called("read_pdf", "0003"), called("search_files"))`; `invoice-mismatch` `looked_at_every_invoice`; contract tasks `any_of(called("read_pdf", "supply-agreement"), called("search_files"))`; `excel-row-count` and `excel-empty-rows` `called("read_excel")` plus a second check `paged_through_excel` (read_excel called at least twice); `contract-summary` `called("read_pdf", "supply-agreement")`.
  Report: the table gets a `trajectory` column (`"3 of 5"`, or `-` when the task has none) and the totals line adds `, trajectory ok in T of R`. A run where the answer passes but the trajectory fails is listed under "## Right answer, skipped work" with its tool call names.

```python
    assert not called("read_pdf", "0003")([pdf(2)])
```

  ```python
  @dataclass(frozen=True)
  class Verdict:
      passed: bool
      reason: str

  JUDGE_PROMPT: str   # system prompt: "You grade an answer against a rubric. Reply with JSON only:
                      # {"pass": true or false, "reason": "one sentence"}. Pass only if every rubric point is met."
  def judge_answer(model: ChatModel, question: str, answer: str, rubric: str) -> Verdict
      # one model call, no tools; the first {...} block in the reply is parsed; none -> Verdict(False, "judge gave no JSON")
  def judge_results(model: ChatModel, results: list[RunResult], tasks: list[Task]) -> None
      # for every result whose task has a rubric: passed = judge verdict (and error is None); reason stored in result.judge_reason
  ```

  2. The same three bullets, each padded with two sentences of filler: pass. "Length should not matter."
  3. Three bullets, 1.5% missing: fail. "A rubric point is missing."
  4. Three bullets, confident and long, with an invented clause ("a 5% discount for early payment"): fail. "Made-up content, written confidently."
