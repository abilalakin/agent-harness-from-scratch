# Step 4: MCP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the ERP database's SQL tools over MCP from our own server, and make the harness an MCP client that loads those tools as ordinary `Tool`s.

**Architecture:** `mcp_server.py` wraps the existing `sql_tools` functions in an `MCPServer` and runs over stdio. `mcp_client.py` holds an `McpConnection`: one background thread runs an asyncio loop, and one long-lived task owns the MCP `Client` from connect to close, while sync methods submit calls to that loop. `make_mcp_tools` turns each server tool into a `Tool` named `mcp__<server>__<tool>`. The agent loop does not change.

**Tech Stack:** `mcp` 2.x Python SDK (`MCPServer`, `Client`, `stdio_client`, `StdioServerParameters`). Checked against `mcp==2.3.0` with a throwaway spike before writing this plan.

**Spec:** `docs/design.md`, step 4. Builds on step 3 (`docs/superpowers/plans/2026-11-03-step-3-data-tools.md`).

## Global Constraints

- Use the official `mcp` SDK (`mcp>=2.3,<3`). No hand-written JSON-RPC.
- The MCP server reuses `sql_tools.describe_tables` / `sql_tools.run_sql`, so the read-only locks, row limit and time limit come along unchanged.
- The agent loop (`agent.py`) does not change. MCP tools are plain `Tool`s.
- The server's stdout is the protocol channel. Nothing in the server may `print`.
- Tests are offline and need no model. Server tests connect in-process; one test starts the real subprocess.
- Every task updates `docs/architecture.md` and `docs/steps/04-mcp.md`.
- Commits: show files and message, wait for the user's OK, then commit.

## Facts from the spike (mcp 2.3.0)

- `from mcp.server.mcpserver import MCPServer`; tools via `@server.tool()`; input schema comes from type hints, description from the docstring; `server.run("stdio")`.
- `from mcp import Client, StdioServerParameters`; `from mcp.client.stdio import stdio_client`. `Client(server_instance)` connects in-process (tests). `Client(stdio_client(params, errlog=file))` starts a subprocess.
- `list_tools().tools[i]` has `.name`, `.description`, `.input_schema`. `call_tool(name, args)` returns `CallToolResult` with `.is_error` and `.content` (items with `.text`).
- A tool that raises a normal exception reaches the client as only `Error executing tool <name>`; the message is lost. Raising `mcp.server.mcpserver.exceptions.ToolError(msg)` keeps it: `Error executing tool <name>: <msg>`.
- Unknown tool → `is_error=True`, text `Unknown tool: <name>`. Bad arguments → `is_error=True` with the pydantic validation message.
- The connection must be entered and exited **in the same asyncio task** (anyio cancel scopes). Entering in one `run_coroutine_threadsafe` call and exiting in another raises `RuntimeError: Attempted to exit cancel scope in a different task`.
- `stdio_client` passes the subprocess only a small safe set of environment variables by default, so `HARNESS_DATA_DIR` would not arrive. The database path goes in as a command-line argument instead.
- The server writes logs to stderr (e.g. `Tool 'x' failed: ...`). `errlog` decides where they go.

## Review Focus

1. **Server won't start** (bad command, crash on import, exits at once). The harness says so within a few seconds, not after the full call timeout. → Task 4b test.
2. **Errors crossing the protocol.** A refused write or a bad column must reach the model with the real SQLite message, not just "Error executing tool". → Task 4a and 4b tests.
3. **Bad arguments from the model** (missing `query`, wrong type). Checked by the server now, not by `run_tool_call`; the validation message reaches the model. → Task 4b test.
4. **Shutdown.** `/exit`, Ctrl+D or Ctrl+C at the prompt close the connection and end the server process. A call after `close()` gives a clear error, not a hang. → Task 4b test, plus a manual `ps` check.
5. **Name clash.** Built-in `run_sql` and the server's `run_sql` must not collide. MCP tools are named `mcp__erp__run_sql`. → Task 4b test.

def call(server, fn):
    """Run fn(client) against the server in-process and return its result."""
    async def go():
        async with Client(server) as client:
            return await fn(client)
    return asyncio.run(go())

def test_lists_both_tools_with_schemas(data_dir):
    tools = call(build_server(data_dir / "erp.db"), lambda c: c.list_tools())
    by_name = {t.name: t for t in tools.tools}
    assert set(by_name) == {"describe_tables", "run_sql"}
    assert by_name["run_sql"].input_schema["required"] == ["query"]
    assert "describe_tables" in by_name["run_sql"].description   # tells the model to look first

def test_run_sql_returns_rows(data_dir):
    r = call(build_server(data_dir / "erp.db"), lambda c: c.call_tool("run_sql", {"query": "SELECT COUNT(*) AS n FROM customers"}))
    assert not r.is_error and r.content[0].text.splitlines() == ["n", "50"]

def test_refused_write_keeps_the_real_message(data_dir):
    r = call(build_server(data_dir / "erp.db"), lambda c: c.call_tool("run_sql", {"query": "DELETE FROM customers"}))
    assert r.is_error and "readonly" in r.content[0].text

def test_missing_database_gives_make_data_hint(tmp_path):
    r = call(build_server(tmp_path / "erp.db"), lambda c: c.call_tool("describe_tables", {}))
    assert r.is_error and "uv run make-data" in r.content[0].text

### Task 4b: The harness as an MCP client

**Files:**
- Create: `src/harness/mcp_client.py`, `tests/test_mcp_client.py`
- Modify: `src/harness/config.py`, `tests/test_config.py`, `src/harness/cli.py`, `.gitignore`, `docs/architecture.md`, `docs/steps/04-mcp.md`

**Interfaces:**
- Consumes: `Tool`, `run_tool_call` (step 2); `build_server`, `SERVER_NAME` (4a); `make_sql_tools` (3c).
- Produces:
  ```python
  # config.py: Settings gains
      sql_via: str = "builtin"     # HARNESS_SQL_VIA: "builtin" or "mcp"; anything else → ValueError at load_settings

  # mcp_client.py
  class McpConnection:
      def __init__(self, server: StdioServerParameters | MCPServer, errlog: TextIO = sys.stderr,
                   timeout: float = 30.0): ...
          # starts a daemon thread with its own event loop; one task (_own_connection) enters the Client,
          # signals "connected", waits for a stop event, then exits the Client in that same task.
          # StdioServerParameters → Client(stdio_client(server, errlog=errlog)); MCPServer → Client(server).
          # If the owner task ends before connecting, raise RuntimeError(f"MCP server failed to start: {error}")
          # as soon as that happens (poll the owner future every ~0.1 s), not after `timeout`.
      def list_tools(self) -> list[mcp.types.Tool]
      def call_tool(self, name: str, arguments: dict) -> mcp.types.CallToolResult   # waits at most `timeout`
      def close(self) -> None        # idempotent; after it, list_tools/call_tool raise RuntimeError("MCP connection is closed")

  def make_mcp_tools(connection: McpConnection, server_name: str) -> list[Tool]
      # one Tool per server tool: name f"mcp__{server_name}__{t.name}", description t.description or "",
      # parameters t.input_schema, fn(**arguments) -> joined .text of the result's content;
      # if result.is_error: raise ValueError(that text), so run_tool_call reports "Error: tool '<name>' failed: ..."
  ```

def test_server_that_dies_fails_fast(tmp_path):
    params = StdioServerParameters(command=sys.executable, args=["-c", "import sys; sys.exit(3)"])
    start = time.monotonic()
    with open(tmp_path / "server.log", "w") as log, pytest.raises(RuntimeError, match="failed to start"):
        McpConnection(params, errlog=log, timeout=30)
    assert time.monotonic() - start < 10

def test_calls_after_close_fail_clearly(data_dir):

- [ ] **Step 4: Implement `mcp_client.py`.** The shape proven in the spike:

```
__init__: loop = new_event_loop(); Thread(target=loop.run_forever, daemon=True).start()
          owner = run_coroutine_threadsafe(_own_connection(...), loop)
          wait for "connected" in ~0.1 s slices; if owner.done() first → RuntimeError("MCP server failed to start: ...")
_own_connection: stop = asyncio.Event(); async with Client(...) as client: self.client = client; connected.set(); await stop.wait()
_run(coro):  if closed → RuntimeError("MCP connection is closed"); run_coroutine_threadsafe(coro, loop).result(timeout)
close:       if already closed → return; loop.call_soon_threadsafe(stop.set); owner.result(timeout); loop.call_soon_threadsafe(loop.stop)
```

A short comment at the top of the file explains why: the SDK is async, the harness is not, and the connection must open and close in one task.
